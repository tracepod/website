Harden containers based on what they actually do at runtime.

Tracepod attaches an eBPF sensor to your running workloads, captures every file they touch, and produces a minimised OCI image, seccomp allowlist, AppArmor profile, and signed SBOM — automatically. Attack surface you can measure, not guess.

How it works

Four outputs from one profiling run

A single eBPF sensor session produces a complete hardening bundle — no guesswork, no allow-all defaults.

01

Profile

eBPF sensor attaches to running containers via kprobes, capturing every openat() syscall — filtered by cgroup/namespace, zero kernel module required.

02

Minimise

Only observed files — plus recursively resolved ELF shared libraries and language-runtime companions — go into the new OCI image layer. Every file tagged by source.

03

Harden

Generate a seccomp syscall allowlist and AppArmor profile directly from observed runtime behaviour — precise, not over-permissive.

04

Sign & attest

CycloneDX and SPDX SBOMs generated by syft, signed with cosign, pushed alongside the image. Auditable, portable, supply-chain ready.

Confidence scoring

Every file carries its source — so you can trust the result.

Most container-slimming tools give you a plain file list. Tracepod tags every path with the observation source: direct eBPF observation, inferred ELF dependency, inferred runtime companion, or manually added. That distinction is the foundation of confidence scoring — you see exactly what you’re shipping and why.

A minimised image that crashes in production is worse than not hardening at all. Tracepod is designed to eliminate that outcome.
